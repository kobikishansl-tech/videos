# MODULE 1 — CHARACTER CREATION ENGINE

## 1.1 Design decision: 2.5D "flat-render" characters (three implementation options compared)

| option | how | integration quality | cost/perf in our env | verdict |
|---|---|---|---|---|
| **A. SVG/card billboards in 3D scene** (proven: Dancing Plague villagers) | 2D character drawn as layered SVG groups, rendered to a canvas card, placed in the 3D scene at world coordinates; camera math makes perspective correct for free | very good; true 3D position, scale by distance, ground-contact anchor + painted contact shadow | ~0.1 s/char/frame at px≤1000 canvas (measured: 12-villager pool at px300 + 8 fps quantization fits 4 GB with check ok) | **PRIMARY** |
| B. True 3D toon meshes | extruded/flat-shaded low-poly character meshes in THREE.js | best occlusion/lighting, worst look control; toon shading in THREE needs custom shaders | authoring sculptural characters is impossible to author sculpturally without artists; risk high | fallback for hero moments only |
| C. AI-image character sheets + video gen | generate reference sheets, animate with AI video | identity drifts frame-to-frame (UNVERIFIED at our scale; industry-known inconsistency) | no local GPU; per-shot cost external | rejected as core; allowed for concept art only |

## 1.2 Character spec (original, numbers anchored to measured style)

- **Proportions**: 2.75 head-units tall total; head = 1 unit, body = 1.75. Head width ≈ 0.8 unit (round, oversized). Leg length 0.6; arm 0.55. Eyes: two ovals spaced 0.36 units, height 0.14. Mouth: single arc/slot, width 0.18. No noses. (These match the observed style grammar: `reports/08 §1`, at poster resolution.)
- **Facial design**: eyes dominate; expression = eye scale + mouth arc shape only (4-curve faces).
- **Hair/clothing**: 2 apparel tokens per character (top color + accessory), chosen from the film palette; silhouettes differentiate characters more than detail does (reads correctly at 50×90 px — the reference's own test).
- **Palette**: each film picks 6 colors (2 char primaries + 4 env); characters draw from slots so the cast harmonizes (per-film tightness — `reports/08 §4`).
- **Consistency mechanism** (the actual product of Module 1): a **CHARACTER CARDS directory per production** — original PDF/PNG-like references (generated by rendering the rig itself):
  1. front / side / three-quarter renders (rig rotations 0° / 90° / 40°),
  2. expression sheet (4 core: alarm, laugh, scared, earnest — plus neutral, 6 total),
  3. pose/action sheet (idle, walk-frame-1, walk-frame-2, act, react).
  Rendered FROM the same rig used in the film, so references can never drift from production. This is the key originality of the design: **references are renders of the rig, not separate artifacts.**

## 1.3 2D-in-3D workflow (feeds Module 3)

Character = structured document: `pose groups` (head, torso, arms ×2, legs ×2, prop) with
rotation/translation parameters; the engine composes group transforms per animation state.
Positioning in 3D = one world-space anchor point + facing angle + scale constant; the scene
camera does the rest. Detail in Module 3.

## 1.4 Automation / human split
- Automated: palette slotting into rig; reference-sheet rendering; 3/4 view generation; pose interpolation.
- Human: silhouette approval (one look), palette pick (one dropdown), per-film cast list.

# MODULE 2 — 3D WORLD GENERATION

## 2.1 Core idea: SET FAMILIES + MODULAR PIECES (not a city generator)

Measured reality (report 08 §6): the reference re-deploys *archetypes*, not literal environments.
So our world system = **5 set families, each a parametric builder**, exactly matching the
environment taxonomy observed on `cats_environments.jpg`:

| set family | covers user's list | build approach |
|---|---|---|
| `urban` | cities, streets, buildings, shops | parametric box architecture: block masses + window grids + storefront strips; street = corridor with sidewalk slabs, lamps, props (signpost, hydrant, crate) |
| `domestic` | houses, offices, interiors | room-box builder: floor/walls/ceiling, furniture library (table, chair, bed, desk, shelf, stairs — stairs proven in our build), window+light-shaft piece |
| `industry` | factories | gantry/silo/pipe kit, smoke volumes, conveyor pieces |
| `nature` | nature, large landscapes | terrain plane + hill mesh + tree kit (billboarded or low-poly), sky dome with measured day gradient (proven: `top #3e7fd2 / mid #70adf1 / horizon #b8d0ec`) |
| `period` | historical environments | nature/urban pieces re-skinned in period palette + era props (torches, market stalls, ships — deck+barrel+railing pieces proven in our build) |

## 2.2 Procedural generation policy
- **Deterministic builders with seeds**: every set is `buildSet(family, params, seed)` → same seed = same world (reproducibility requirement from the original task).
- **Reusable = the pieces, not the scenes**: full set assemblies are per-film; the piece library (λ: wall, window, door, stair, tree, lamp, barrel, railing, signpost, vehicle shell) is the reusable layer.
- **Detail budget by distance** (from our depth-layering finding, report 09 T2): foreground/midground get real geometry; far layer gets gradient slabs + fog. Portrait FOV (~27° half-width) hides cheap far layers — this is a measured advantage we exploit.

## 2.3 Set-piece quality bar (from measured lighting/depth discipline)
- Every exterior: bright-top/dark-bottom composition (top_luma − bot_luma ≈ +0.1–0.15) — sky vs ground.
- Every interior: one motivated light source; ceilings catch directional light.
- One environmental-animation layer minimum per set (flag, smoke, water bob, dust motes, crowd) — required by the "change every second" rule.

## 2.4 Automation / human split
- Automated: set assembly from parent scene record; palette application; sky/lighting preset; depth-cull optimization.
- Human: one shot-list pass checking silhouette readability + "wow frame" choice for opener.

# MODULE 3 — CHARACTER AND WORLD INTEGRATION (critical module)

## 3.1 The three problems and the chosen solution stack

**Perspective + scale + movement through 3D space.** Option A billboards are placed via world-space
anchor conversion (`spot(set, anchor)` → per-set group transform, proven). The scene camera
projection gives correct perspective and distance scaling automatically; walking = animated anchor
path, so characters genuinely move through 3D space.

| problem | solution (Option A) | measured evidence |
|---|---|---|
| correct perspective | world-space anchor + camera projection | our pool villagers rendered at correct scales across 5–9 m corridor |
| character scale | scale constant per character height (m), not per-view fudge | anchor distance math; portrait drop-out rule below |
| ground contact | feet at y=0 anchor; ground plane raycast for slopes | set terrain pieces define y=0 local plane |
| contact shadows | painted radial-gradient blob under each character (opacity ∝ key intensity) | flat look matches cel style; true shadow map cost unnecessary |
| **occlusion** | per-set render layers: characters drawn in 3D depth order via per-frame z-sort against occluder boxes registered per set | our known failure (pool below-frame) was staging, not occlusion; z-sort list is a build-time table |
| depth ordering vs DOF | characters as canvas cards accept the same fog/grade pass as scene | single grade pass over composited frame |
| lighting consistency | per-character tint parameter driven by set lighting preset (warm interior → warm tint; dark rig → silhouette tint) | measured: dark scenes read silhouettes; tinting reproduces that |
| reflections | only via floor piece shader in hero shots; default OFF | perf |
| camera synchronization | characters are scene children of the set group — inherit ALL camera motion by construction | proven (camera = pure function of t) |

## 3.2 The two hard rules discovered in our own build (must stay in spec)
1. **Portrait ground rule**: a ground-standing character closer than ~4–5 m to a 1.5 m-high camera drops below frame (vertical FOV geometry). Auto-staging validator: reject staging closer than computed min distance, unless a high-angle view is set.
2. **Set-visibility rule**: characters parented to a set are hidden when another set draws; cross-set beats must be staged inside the currently drawn set's group. Engine builds a lint rule for this (our view-7 bug's permanent cure).

## 3.3 Compare with alternatives (required by the task)
- **Projective 3D→2D keying (Unreal/Blender compositing)**: higher ceiling for shadow/occlusion realism, but needs GPU + operator; our 4 GB/CPU-only env makes this the wrong default. Keep as escalation path if we ever get GPU.
- **Fully-flat parallax staging (3 layers, no true 3D)**: cheapest, but breaks measured classic beats (orbit feels, whip-through-door moments). Rejected as primary.
- **Hybrid: billboards + true-3D hero meshes** — the actual recommendation for later: heroes stay billboards; occasional true-3D props for interaction beats (doors opening, objects thrown).

## 3.4 Automation / human split
- Automated: anchor→screen projection for framing check; min-distance validator; set-parenting lint; per-character tint from light preset; z-order table generation.
- Human: approve framing stills per scene (batch of ~15–30 images per film, one click-through).

# MODULE 4 — CINEMATIC CAMERA ENGINE

## 4.1 Design: a typed VIEW LIBRARY, generated from the scene record

Every camera move is one of 13 typed moves, each a pure function `f(t, params) → cam`
(proven pattern: our `story.js` cameras). The scene record names the move + params; nothing is
hand-animated numeric-plumbing.

| move | params | measured reference anchor |
|---|---|---|
| ESTABLISH (wide hold) | anchor, height, fov 40–46 | opening holds 2.0–7.8 s |
| MED / CLOSEUP | anchor subject, distance band | subj_x 0.43–0.55 band |
| LOW-ANGLE / HIGH-ANGLE | camera y below/above subject eye | VS1Z shot 2 high; shot 0 low |
| TRACK (follow anchor path) | path, lead | QlDPM road beat |
| DOLLY IN/OUT | distance ramp | push-in on reveal |
| ORBIT | center, radius, arc | hero 3/4 reveal |
| CRANE | y + distance ramps | act transitions |
| OTS | overcast framing w/ foreground occluder | dialogue scenes |
| PUSH / PULL (punch-in) | quick 1–2 s fov or distance snap | hook montage |
| WHIP (as cut) | 4–8 frame directional blur at boundary | all large-diff transitions; whip happens AS cut, never intra-shot (report 06 #3) |
| HANDHELD FEEL | micro-noise on any of the above | optional life layer |
| FROZEN (near-hold + wobble) | anchor, ±0.008 bob | low-change shots (min 0.066 diff — still alive) |
| POSTCARD (ending) | composed final frame | view-28 moon rule in our build |

## 4.2 Script→camera mapping (camera directions generated from script)
Deterministic mapping table narration→shot type (from measured cut grammar, reports 03/06/09):
- beat 1 "scene-setting clause" → ESTABLISH (2–7.8 s)
- each new location in script → MARKER: new set + ESTABLISH variant
- keyword classes → move type: "then/suddenly/one day" → PUSH or WHIP+cut; numbers/names → CLOSEUP; dialogue → OTS pair; "but/however" → ORBIT or LOW-ANGLE; final clause → POSTCARD
- hook montage = first 40 % of runtime; hold relaxation allowed after 60 % mark.

## 4.3 Camera QA (automated, numeric — our own originals)
Per rendered shot compute the same metrics we used on the reference (`shots.csv` schema):
subj_x ∈ [0.40, 0.60], top/bottom luma asymmetry sign check, in-shot change ≥ 0.07/s,
no shot fully outside luma band except engineered dips. A camera move that fails the band is
flagged with the violating frame attached.

# MODULE 5 — ANIMATION ENGINE

## 5.1 Architecture: STATE MACHINE over rig groups + procedural cycles
- Rig groups: head / torso / armL / armR / legL / legR / prop / face.
- **States** (user's list → 6 primitives): `idle-wobble` (continuous sine bob 0.008 @ 2.2 Hz — proven), `locomote` (walk/run: leg/arm phase-offset rotation formulas + vertical bob 2/stride), `gesture` (arm key angles with 0.35 s ease), `orient` (look/turn: head yaw then torso yaw 0.2 s apart — follows first), `sit-stand` (presets: two keyframe tables + 0.4 s blend), `react` (expression change + 0.15 s startle hop).
- **Talking**: mouth slot opens on syllable energy from our own word timestamps (`voice/words.json` — kokoro word times are exact; narration sync is therefore exact-by-construction, not estimated).
- **Object interaction**: prop group parents to hand anchor for the beat duration (pickup = prop reparent + hand angle key; throw = reparent to scene physics-lite ballistic path).
- **Environmental interaction**: crowd/cloud/flock layers bob with per-index phase offsets (proven pool machinery).
- **Timing**: 8 fps pose quantization for crowds, 30 fps for heroes (measured perf trade-off, 4 GB cap).

## 5.2 Investigated approaches — verdicts
- **Keyframes**: needed only for sit-stand + hero moments; engine stores 2-pose tables (start, end) + easings, NOT animation-editor timelines.
- **Procedural**: the default for everything cyclic — this is how one person gets 12+ animated villagers in a 62 s film (proven).
- **Retargeting/mocap**: NO mo-cap input available locally; BVH retarget would need Blender + GPU pipeline; rejected.
- **AI-assisted animation**: optional text→pose-helper for gesture scripting later; NOT core (unverifiable quality, adds nondeterminism).

## 5.3 Automation / human split
- Automated: state scheduling from scene record verbs; rhythmic sync to bed drums; face pose from word energies.
- Human: acting notes per scene ("more frantic", "hesitant") — a verb+intensity column the human edits.

# MODULE 6 — LIGHTING AND RENDERING

## 6.1 Lighting: 3 preset rigs per film (from measured evidence)
| rig | config |
|---|---|
| DAY | directional sun key (el ~0.5) + hemi fill (key 4.0 / hemi 1.15 measured) + sky gradient; shadows soft-blob |
| WARM INTERIOR | one point light at motivated source + low ambient; warm grade |
| MOOD-DIP | ambient only + heavy contrast; silhouettes; target luma ≤ 0.28 |

## 6.2 Render pipeline (proven end-to-end in our build)
- Headless Chromium + THREE.js scene graph → per-frame capture → ffmpeg silent assembly → audio mix (VO + synth bed + SFX) → loudness normalize −14 LUFS.
- Measures: 30 fps, 1080×1920; CPU-only ≈ 2.8 s/frame (62 s film ≈ 92 min wall) — accepted cost; DETAIL BUDGET: crowd cards px≤300 & 8 fps, hero cards px 1000 @ 30 fps.
- **Grade** (per film, locked): sat 1.3–1.35, contrast 1.02, warm 0.45, lift 0.02–0.035, vignette 0.16 (measured values from our look pass, matching reference bands).
- **AO**: baked-in painted shading in piece textures + gradient contact shadows (true SSAO too slow CPU-side). **DOF**: fog + backdrop blur only for far layers at 50×90 test; true DOF off. **Motion blur**: only on WHIP boundaries (directional smear overlay), off elsewhere (cost).
- **QA gates on OUR renders** (this is where we exceed the reference investigation): per-shot luma/sat/ink/subj_x auto-report → compare to spec bands from report 10 §9.

# MODULE 7 — SCRIPT-TO-SCENE AUTOMATION (central workflow)

## 7.1 Pipeline (each stage exists today in prototype form — noted)

| stage | mechanism | status |
|---|---|---|
| SCRIPT | one Markdown file, scene headers + narration lines | proven |
| EXACT TIMESTAMP EXTRACTION | TTS once, word-level timestamps returned by engine (`words.json`) — **timestamps are measured from actual audio, never invented** | proven (228 words timed) |
| NARRATION SEGMENTATION | sentences → beats; beat = max 2 sentences, cut-aligned to nearest word boundary | proven (28 views) |
| VISUAL STORYBOARD | beat → scene record draft (auto rules: location change → new set; keyword → camera verb) | to build |
| CHARACTER REFERENCES | rig → rendered sheets (Module 1.2) | to build |
| ENVIRONMENT REFERENCES | set builder → 3-view preview renders per set | to build |
| SCENE CONSTRUCTION | scene record → staging + set + cast instantiation | proven pattern |
| CAMERA DIRECTIONS | typed move library, params from record (Module 4.2) | proven pattern |
| ANIMATION | state scheduling from record verbs (Module 5) | proven pattern |
| RENDERING | stills → check gate → full render with bed | proven |
| VIDEO ASSEMBLY | audio mix + loudness + QA report | proven |

## 7.2 The SCENE RECORD (structured data per scene — the contract object)

```
scene = {
  id, idx,                      // stable ids
  t_start, t_end,               // EXACT — copied from words.json, never normalized
  narration,                    // verbatim segment
  word_times: [[w, t, d]],      // measured audio timestamps
  set:   { family, params, seed, preset },   // → Module 2 builder
  cast:  [ { char, variant, palette_slot, anchor, actions: [(verb, t0, t1, intensity)],
             facing, expressions } ],
  camera: { move, params, t0, t1 },          // → Module 4 move library
  lighting: { rig, key_int, mood_dip: bool },
  props: [ { piece, anchor, action } ],
  sfx:   [ { name, t, gain } ],              // at cuts/beats only (measured grammar)
  grade: locked_per_film,
  qa:    { subj_x_band, luma_band, dip_ok }
}
```

Immutable rule carried from the original task: **t_start/t_end always equal the word timestamps;
no tool may round, normalize, or invent them.** Rendering maps them frame-exact at 30 fps via
`startOf(i) = V[i].t − frames/FPS` earlier-enter pattern (whips enter early — proven).

## 7.3 Automation / human split
- Automated: everything after the human writes the script + edits the record's `actions`/`camera` overrides.
- Human: script itself; one review of the auto-drafted scene records (table view); approve reference sheets; approve framing stills.

## 9.7 Technical risks & mitigations
1. **Render time/4 GB ceiling** → detail budget (px, fps quantization), staged culling, nightly renders detached; proven mitigations already shipped in our build.
2. **Crowd visibility in portrait framing** → auto min-distance validator (our measured failure turned into a rule).
3. **Character identity drift** → references ARE rig renders; palette slots immutable per film.
4. **Scene-record authoring burden** → auto-draft from script + default params; human edits a table, not JSON plumbing.
5. **Look plateau below reference-grade environments** → measured geometry budget + fog/palette covers era-2 band; escalation path = GPU + Blender/Eevee only if CPU ceiling is genuinely hit.
6. **Audio quality ceiling (synth bed)** → no measured reference available (storyboards carry no audio); we keep our proven bed+SFX pattern and flag remaining audio polish as future work.
